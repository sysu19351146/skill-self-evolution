# 图3：六阶段演进路径

对应正文：RQ2。建议输出文件：`assets/03-evolution-path-whiteboard.png`。六个阶段是实际顺序概括，不添加日期、版本号、虚构分支或阶段收益。

生成一张"专家白板教学"风格的手绘信息图，主题：工作方法的六阶段演进——从能力构建到反馈驱动的修改，横版16:9，背景为干净白色白板或浅灰网格纸。

**视觉元素：** 使用真实马克笔手绘质感的粗细不均线条、箭头和圆角方框。六个阶段采用两行三列的连续流水线布局，上行从左到右，下行从右到左，形成折返路径。每个节点使用大号中文标题、一枚图标和一条短说明；节点序号只标注一至六。颜色用于区分阶段，不表示阶段优劣。

**画面左上：** 蓝色圆角方框，内画简笔画积木图标，标题“一、能力构建”，说明“生成、验证、分析、修复”。由此到上中节点画粗蓝色实线箭头，标注“投入任务运行”。

**画面上中：** 橙色圆角方框，内画简笔画放大镜图标，标题“二、问题发现”，说明“重复读取与过程负担”。到右上节点画粗橙色实线箭头，标注“定位冗余”。

**画面右上：** 黄色圆角方框，内画简笔画剪刀图标，标题“三、流程精简”，说明“减少通用流程的重复指导”，旁注“结合模型能力变化”。到右下节点画向下的粗实线箭头，标注“收敛重复操作”。

**画面右下：** 绿色圆角方框，内画简笔画工具箱图标，标题“四、脚本整合”，说明“用脚本获取信息与执行验证”。到下中节点画向左的粗绿色实线箭头，标注“运行暴露失败”。

**画面下中：** 深蓝色盾牌形方框，内画简笔画带对勾的清单图标，标题“五、稳定性补强”，说明“可运行、真执行、结果一致”。到左下节点画向左的粗蓝色实线箭头，标注“检查整体效果”。

**画面左下：** 紫色圆角方框，内画简笔画天平图标，标题“六、评测迭代”，说明“比较质量与开销”。从此处沿画面左边缘画紫色虚线箭头回到问题发现区域，标注“新问题触发下一轮”。

**画面右下角：** 在节点区外保留空白，画一个简笔画火柴人老师拿着马克笔指向“稳定性补强”，旁边画一个对话气泡写“失败也会让规则增加！”不要遮挡第四阶段节点。

**文字：** 全部用真实手写风格，文字清晰可辨。标题大而醒目“工作方法怎样一步步改变”，副标题“精简流程、整合脚本、补强约束，共同接受运行检验”。底部写“问题定位 + 定向修改 + 结果比较 = 下一版方法”。不出现每个阶段的量化收益。

**内容结构：** 六节点折返流水线，主要路径为带文字标注的粗实线，下一轮的条件路径用带标注的虚线。图面只解释演进顺序，不画自动候选筛选、自动发布等未实现功能。留白30%以上，整体干净、专业、像课堂白板教学图，所有文字必须100%清晰可读，无模糊、无重叠，高对比度。
